AD Lab Project

Project Name: Windows Server and Active Directory Home Lab

Purpose: The purpose of this project is to build a virtual 
Windows domain to practice IT support and system administration, 
including managing users, computers, permissions, and Group Policy.

Project Outcome: Built an isolated Active Directory 
lab in Hyper-V with a Windows Server 2025 domain 
controller and a Windows 11 Pro client. Resolved a 
duplicate IP conflict, verified DNS and domain sign-in 
from the client, and tested that a Group Policy restriction 
applied to the domain test user while the local account 
retained access.

DNS Verification and Troubleshooting

Verified the following DNS zones exist:
- ad.rjlab.test
- _msdcs.ad.rjlab.test

Confirmed the forward Host (A) record:
dc01.ad.rjlab.test -> 10.10.10.10

Issue:
The initial nslookup returned the correct IPv4 address
but displayed timeouts and identified the DNS server
as Unknown.

Investigation:
Increasing the timeout did not resolve the delays.
An explicit A-record query using the fully qualified
name with a trailing period removed the additional
lookup timeouts. An initial server-identification
timeout remained.

The reverse lookup zone had not been configured.

Resolution:
Created an Active Directory-integrated reverse zone:
10.10.10.in-addr.arpa

Configured replication to DNS servers on domain
controllers in ad.rjlab.test and secure dynamic
updates only.

Created DC01's PTR record by selecting "Update
associated pointer (PTR) record" on its Host (A) record.

Reverse mapping:
10.10.10.10 -> dc01.ad.rjlab.test

Verification command:
nslookup -type=A dc01.ad.rjlab.test. 10.10.10.10

Result:
The DNS server was identified by name, the correct
IPv4 address was returned, and no timeouts occurred.

Screenshot:

Client Network Configuration and Troubleshooting

Intended CLIENT01 settings:
- IPv4 address: 10.10.10.20
- Subnet mask: 255.255.255.0 (/24)
- Default gateway: None
- Preferred DNS server: 10.10.10.10 (DC01)

The first DNS lookup failed while CLIENT01 was still
using an automatic 169.254.x.x address. After switching
to static settings, DNS still failed. On DC01, ipconfig
reported 10.10.10.10 as Duplicate. Checking CLIENT01
showed it had also been assigned 10.10.10.10.

This explained why CLIENT01 could ping 10.10.10.10
even while DC01 was off: it was pinging itself.

Corrected CLIENT01's IP address to 10.10.10.20 and
kept its DNS server set to 10.10.10.10. Restarted DC01
and verified that its address showed as Preferred.

From CLIENT01, ran:
nslookup -type=SRV _ldap._tcp.dc._msdcs.ad.rjlab.test.

The query used DC01 at 10.10.10.10 and returned
dc01.ad.rjlab.test on LDAP port 389. This verified
that the client could discover the domain controller.

Shared Folder Permissions Lab

Active Directory Security Groups

On DC01, I created two Global Security groups in the
Users container of ad.rjlab.test:

- Finance-Read: For users who should be able to open
  and read files in the Finance shared folder.
- Finance-Modify: For users who should be able to read,
  create, edit, and delete files in that folder.

I verified that both groups appeared in Active Directory
Users and Computers. I created separate groups so I can
manage access through group membership instead of assigning
permissions to each user individually.

Created a standard domain test account named finance.reader
to verify read-only access from CLIENT01. Added finance.reader 
to the Finance-Read security group and verified that Finance 
Reader appeared on the Members tab. 

Created a standard domain test account named finance.editor
to verify Modify access from CLIENT01. Added finance.editor to 
the Finance-Modify security group and verified that Finance 
Editor appeared on the Members tab. 


Folder and Share Configuration

Created C:\LabShares\Finance on DC01 as the folder
for the Finance permissions lab. The folder had not
yet been shared over the network.

Disabled NTFS permission inheritance on C:\LabShares\Finance
and converted the inherited entries to explicit permissions.
Removed both Users entries to prevent broad access. Kept the
Administrators, SYSTEM, and CREATOR OWNER entries.

Granted RJLAB\Finance-Read Read & execute access to
C:\LabShares\Finance and its subfolders and files.
Verified the entry in Advanced Security Settings.

Granted RJLAB\Finance-Modify Modify access to
C:\LabShares\Finance and its subfolders and files.
Verified that Finance-Modify had Modify access and
Finance-Read retained Read & execute access.

Published C:\LabShares\Finance as \\DC01\Finance.
Removed Everyone from the share permissions and granted
Finance-Read Read access and Finance-Modify Change and
Read access. See the three client access tests below.

Created Finance-Test.txt in the Finance shared folder
to test read and write permissions from CLIENT01.
